# Math Training Machine

An arcade style mental arithmetic trainer. You get 60 seconds of rapid fire
questions about **sums and differences of positive and negative numbers**,
answer them with a single key press, and the best runs end up on a shared
leaderboard.

```
   (-7) + 12 = ?          [1] 5   [2] 19
                          [3] -5  [4] 17
```

No typing numbers anywhere - every question is a four-option multiple choice
problem, so the game stays fast: keys `1`-`4` (or `A` `S` `D` `F`) answer,
`ENTER` starts a round, `ESC` backs out.

## Stack

| part       | tech |
|------------|------|
| game       | ClojureScript, Reagent, shadow-cljs |
| sound      | Web Audio API, synthesised - no asset files |
| server     | Common Lisp, Clack with the **Wookie** handler |
| storage    | **conskivi** key/value database (file-only backend) |
| protocol   | JSON over HTTP (`/api/leaderboard`) |

## Build & run

Like [focus](https://github.com/turtle-bazon/focus/), the server is
distributed as **one self-contained binary**: the frontend is compiled by
shadow-cljs, baked into `server/static-assets.lisp` as base64 and dumped into
the SBCL core image with `program-op`, so the binary needs no Lisp, no
`public/` and no other files at run time.

```sh
make build          # frontend + embedded assets + build/math-training-machine
make run            # run straight from source (fresh files, no image dump)
make dev-start      # run the built binary in the background (log: /tmp/mtm.log)
make dev-stop       # stop it
make tests          # API smoke test against a throwaway server (port 8765)
make e2e            # browser end-to-end test (playwright-core)
make mobile         # phone-sized touch probe (390x844)
make clean          # remove build/
```

`make build` = `clean frontend generate-static` + the image dump; set
`BUILD_SUFFIX` to rename the output binary. Static serving order: files under
`public/` on disk when they exist (development, `shadow-cljs watch` rebuilds
are picked up on reload), otherwise the copy embedded in the image.

For development without a binary:

```sh
npx shadow-cljs watch app            # rebuild the game on change
sbcl --non-interactive --load server/run.lisp
```

Then open <http://127.0.0.1:8123/>.

For development run the watcher and the server side by side: the server serves
whatever `public/js/main.js` currently contains, so a rebuild is picked up on
page reload.

## Configuration

Every setting comes from the environment, then the config file, then a
built-in default - in that order. The config file is a Lisp plist,
discovered as `$MTM_CONFIG`, then `./mtm.conf`, `~/.mtm.conf`,
`~/.config/mtm/mtm.conf`, `/etc/mtm.conf`. Copy `mtm.conf.template` to
`mtm.conf` and edit:

```lisp
(:bind-address "0.0.0.0"   ;; 0.0.0.0 to listen on the LAN
 :bind-port 8123
 :data-dir "data/"         ;; conskivi database directory
 :public-dir "public/")    ;; static assets; missing files fall back to
                           ;; the copy embedded in the binary
```

The file is read as data only (reader eval is off), validated at start-up,
and a bad value stops the server with the offending key named. Which file
was used appears in the banner:

```
[mtm] config:  /srv/mtm/mtm.conf
[mtm] listen:  0.0.0.0:8123
[mtm] data:    data/
[mtm] public:  public/
```

Environment variables override the file - convenient for tests and
one-off runs, and all of them are read at **start-up**, never baked into
the binary:

| var            | default      | meaning                          |
|----------------|--------------|----------------------------------|
| `MTM_CONFIG`   | (discovered) | path to the config file          |
| `MTM_PORT`     | `8123`       | TCP port                         |
| `MTM_ADDRESS`  | `127.0.0.1`  | bind address (`0.0.0.0` = LAN)   |
| `MTM_DATA`     | `./data/`    | conskivi database directory      |
| `MTM_PUBLIC`   | `./public/`  | static assets directory          |

`mtm.conf` is ignored by Mercurial (just as focus ignores `focus.conf`);
the template is what gets committed.

## Game rules

* Round length: **60 seconds**.
* A question is worth `100 + speed bonus` points, multiplied by the combo
  multiplier (`x1` up to `x3`, +0.25 per consecutive correct answer from the
  second one on).
* The speed bar under the question drains over 6 seconds. Answer while it is
  full for the maximum bonus; let it run out and the question counts as a miss.
* Wrong answers break the combo. The last 10 seconds tick audibly.
* Difficulty grows every 5 correct answers: operands move from ±10 to ±100.
* Modes: `SUM`, `DIFFERENCE` and `MIXED`.

## Tests

```sh
make tests   # 15 API checks: health, static, traversal, validation, ranking
make e2e     # 18 browser checks: menu -> round (tap + keys) -> 3s miss
             # feedback -> results -> save -> leaderboard
```

`make e2e` needs a server already running (`make run` or `make dev-start`) on
`http://127.0.0.1:8123`; a `?rt=<seconds>` query parameter shortens the round
so the test finishes quickly.

## Playing on a phone

The layout is fluid (`clamp()` type, a 620px breakpoint that stacks the mode
picker and reflows the stats) and every control is a real `<button>`, so the
game is playable by tapping: `node test/mobile.mjs` drives it at 390x844 with
touch emulation - no horizontal overflow, round starts by tap, answers
register by tap. On coarse pointers the keyboard hints in the footer are
replaced with tap hints and controls are padded to a 44px touch target.

## API

`GET /api/leaderboard?mode=sum&limit=20`

```json
{"mode":"sum","entries":[{"rank":1,"id":"...","name":"ada","mode":"sum",
  "score":1240,"correct":14,"total":16,"accuracy":88,
  "best-streak":9,"avg-ms":1450,"ts":741234567}]}
```

`POST /api/leaderboard`

```json
{"name":"ada","mode":"sum","score":1240,"correct":14,"total":16,
 "best-streak":9,"avg-ms":1450}
```

Answers `201 {"ok":true,...}` with the achieved `rank`, or `400` with an
`error` string. Only the top 100 scores per mode are kept.

## Storage layout (conskivi)

```
:lb-sum :lb-diff :lb-mixed   sorted set   entry-id -> score
:rec-<id>                    scalar       entry record plist
```

Ranking comes from `conskivi-zrevrange`, records from `conskivi-put`, and the
store is flushed with `conskivi-save` after every accepted score so nothing is
lost on shutdown.
